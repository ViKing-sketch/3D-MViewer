# Решения по ТЗ v0.2

Владелец закрыл ОВ-1..ОВ-11 в [TZ_Field_BIM_Viewer_v0_2.md](TZ_Field_BIM_Viewer_v0_2.md) (02.11.2026). Ниже те же ответы, коротко. Формат пакета, который пишет текущий конвертер, по-прежнему описан в [package_format.md](package_format.md).

## Что сделано вместо пустого каркаса

Конвертер MVP читает IFC сам, без IfcOpenShell: STEP physical file, единицы, пространственное дерево, типы, Pset/Qto, материалы, классификацию и выдавливание `IfcExtrudedAreaSolid` (прямоугольник, окружность, полилиния). На выходе — `manifest.json`, `meta.sqlite` (FTS5, `spec_views`), `mesh/lod0.glb`, отдельный GLB на элемент и `brep.pack` с мировым AABB. `pkg_validate` и `fbv_core` этот пакет открывают. Оболочка Flutter показывает список, дерево, свойства, фильтр класса, поиск и CSV.

## M0

Полный прототип M0 (STEP/XDE, два устройства, три модели) не выполнен, go/no-go по телефону нет. Отдельная проверка собрала OCCT 7.8.1 под NDK 28.2 для `arm64-v8a` и `x86_64` на API 28 и прогнала коробку с BinTools на эмуляторе Android 9 x86_64. Та же проба, собранная на API 27, прогнана на эмуляторе Android 8.1 arm64-v8a (перевод на хосте x86_64, не телефон). Образ API 28 arm64 на этом хосте эмулятор не включает. Формат `brep.pack` от этого не меняется. Числа — в [m0_report.md](m0_report.md). Пресет `android-arm64` по-прежнему требует `ANDROID_NDK_HOME` и в CI не запускается. Superbuild хоста включается `-DFBV_WITH_IFCOPENSHELL=ON`.

## Технические решения реализации

1. **Парсер IFC.** Раскладка атрибутов — IFC4, с поправкой на `IfcArbitraryClosedProfileDef` IFC2X3 (кривая профиля без `ProfileName`). В пакет попадает каждый экземпляр с GlobalId и раскладкой IfcElement, а не короткий белый список классов. Заголовок `IFC2X3` и `IFC4X3` принимается.
2. **Мешер.** При `-DFBV_WITH_IFCOPENSHELL=ON` основной путь — итератор IfcOpenShell v0.8.5 с ядром Open CASCADE 7.8.1 (`ifcopenshell-occt`). Аналитическое выдавливание (`analytic-extrusion-v1`) остаётся запасным путём для элементов, которые итератор не триангулировал. Сборка без IfcOpenShell по-прежнему только аналитическая. Элемент без меша остаётся в SQLite и в логе с причиной; пропуск GlobalId без `--allow-incomplete` не пишет пакет (код 4, FR-C-16). STEP/IGES по-прежнему требуют XDE (`converter/src/xde_import.hpp`). Меши сверх бюджета `--max-memory` (по умолчанию 64 МБ) сбрасываются на диск по элементу, форма OCCT отпускается сразу после триангуляции. Причины предупреждений попадают в JSON как `warning_reasons`. Зависимости Windows — манифест `vcpkg.json`; суперсборка OCCT передаёт `CMAKE_POLICY_VERSION_MINIMUM=3.5`.
3. **Отдельный GLB на элемент** добавлен к `lod0.glb`, потому что оболочке и отладке нужен один элемент без разбора общего буфера. Это записано в format_version 1.
4. **B-Rep.** `brep.pack` остаётся AABB в мировых метрах (`analytic-box-v1`). Это не точная геометрия и не BinTools. Байты `BinTools::Write` формы OCCT, когда её собрал IfcOpenShell, лежат в `exact_geometry` и `geometry/elements/<id>.brep`. Аналитическая сборка эту таблицу оставляет пустой. Измерения по граням (M3) по этим байтам ещё не считаются.
5. **SQLite** — вендорная amalgamation 3.49.2 (public domain) с `SQLITE_ENABLE_FTS5`, одна и та же на Linux и Windows.
6. **Контейнер.** Каталог и ZIP STORE равноправны. ZIP64 нет (предел записи 4 ГиБ). При открытии ZIP распаковывается во временный каталог.
7. **Лог конвертации** пишется рядом с пакетом (`<output>.log`), внутрь пакета не кладётся.
8. **Flutter.** Данные оболочки читает `package:sqlite3` по той же схеме. `fbv_core` подключается через `dart:ffi`, когда задан `FBV_CORE_LIB`; смоук-тест сравнивает размер `fbv_element_info` и число элементов. На устройстве основным путём остаётся `libfbv_core.so` (SQLite уже внутри неё). Filament — заглушка, план в [rendering.md](rendering.md).
9. **Прототип 3DViewer-main** в репозиторий не вложен: исходники не были приложены к задаче. Каталог не создавался пустым; план стыковки описан в rendering.md.
10. **Лицензия продукта** не выбиралась. Сторонние лицензии — в [licenses.md](licenses.md).

* Сборка MSVC/MinGW и Android NDK в этой среде не запускалась. Для Windows в CI добавлен job `windows-msvc`.
