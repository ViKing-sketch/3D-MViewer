# Синхронизация fbv-sync-1

Один протокол для двух адресов. Локальная сеть — это сосед, который слушает тот же протокол. Корпоративный сервер — тот же протокол на сервере организации. Адрес задаётся в библиотеке и пишется в `.fbv-sync.json` рядом с пакетами. Облака и внешнего сервиса нет. Учётной записи нет.

Слушатель в приложении по умолчанию открывает `127.0.0.1` и свободный порт. Клиент забирает файлы с базового URL из настройки. Проверка ниже гоняет оба конца на loopback. Доступность с другого компьютера в сети зависит от того, на каком адресе запущен слушатель; этот репозиторий чужую сеть не вызывает.

## Что входит

Только содержимое выбранной папки библиотеки:

* файл `*.fbvpkg` и каталог пакета с `manifest.json`, включая файлы внутри каталога;
* sidecar `<пакет>.remarks.json` и каталог `<пакет>.remarks`;
* `<пакет>.bcf`, если он лежит рядом.

Файл, который не является пакетом, замечанием или BCF, в список не попадает. Модель, которой нет в этой папке, не читается и не отправляется. Имена с `..`, пустым сегментом, обратной косой или ведущей точкой отклоняются.

## Запросы

`GET /fbv-sync/manifest` — JSON:

```json
{
  "protocol": "fbv-sync-1",
  "files": [
    {"path": "wall.fbvpkg", "bytes": 4, "sha256": "<hex>", "mtime_utc": "2026-11-09T18:00:00.000Z"}
  ]
}
```

`GET /fbv-sync/file?path=<относительный путь>` — байты одного файла из этого списка. Чужой путь отвечает 404, даже если файл лежит рядом с папкой.

## Кто побеждает

Одинаковый SHA-256 не копируется. Если суммы разные, файл заменяется только когда метка времени удалённой копии строго новее. Более новое локальное замечание не затирается. Лишний локальный файл не удаляется: обрыв не должен стирать то, чего у другой стороны уже нет.

Перед заменой клиент сверяет длину и SHA-256 с манифестом и пишет во временный файл в той же папке, затем переименовывает.
