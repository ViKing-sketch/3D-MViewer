# Очередь приоритетов

Сверка: [requirements_matrix.md](requirements_matrix.md). Дата: 2026-11-08.

Приёмка текущего этапа по ТЗ — M2, сценарии S1–S4 и S7 офлайн. M3 (измерения и контур сечения) упирается в то, что `brep.pack` хранит AABB, а on-device OCCT не выбран отчётом M0. Этот кусок не начинать, пока не сменится кодек B-Rep.

## Уже в открытых PR, не повторять

- PR #2: мешер IfcOpenShell/OCCT, лимит памяти, CI Windows.
- PR #3: Android Filament, импорт пакета, автокадр, портретный выбор.
- PR #4: один clip plane, выбор при срезе, сглаженный зум, короткая панель.

Голова PR #2 (`335452f`) в этот стек не влита. Её исправление configure уже перекрыто коммитами PR #4. Заново его не переносить.

## Этот шаг

FR-M-06 / сценарий S2 в пределах данных пакета format_version 1.

- Фильтр этажа, класса IFC и материала сужает дерево и скрывает остальные элементы в сцене Filament.
- «Показать всё» снимает и этот фильтр.
- «Вписать всё» и стандартные виды кадрируют видимое: скрытые id и элементы вне изоляции в коробку не входят.
- Изоляция, которую фильтр выкидывает, снимается, чтобы сцена не осталась пустой.

Инженерная система (IfcSystem) в пакет не пишется. Отдельный фильтр «система» без этих данных не делается и format_version не поднимается.

## Поиск по свойствам

FR-M-07. Поле поиска строит FTS5-запрос к `fts_elements` (имя, марка, GlobalId, имя типа, текст свойств). Чужие элементы скрываются в дереве и в сцене. Одно совпадение выбирается и кадрируется. Пустой запрос и «Показать всё» снимают ограничение. Индекс уже был в пакете format_version 1, формат не менялся.

## Ходьба по этажу

FR-M-03. Кнопка «По этажу» и пункт меню переключают орбиту и вид от первого лица. Глаз стоит на 1,6 м над верхом плит выбранного этажа (фильтр, иначе этаж выбранного элемента, иначе первый этаж). Старт берётся из мировых AABB: центр пятна, если он свободен, иначе ближайшая клетка вне коробок стен. Дальше высота глаз не меняется. Один палец смотрит, два пальца и колесо идут по горизонтали. Шаг не проверяет ни меш, ни `brep.pack`, поэтому стена не останавливает. «Вписать», стандартный вид и «Показать всё» возвращают орбиту. Смена этажа в фильтре переносит старт, не включая орбитальный кадр.

Образец `testdata/sample_model`: плита 6×4 м, стена-коробка поперёк, колонна. Меш — `analytic-extrusion-v1`, B-Rep — те же AABB. Свободного объёма комнаты в пакете нет, только эти коробки. Выбор точной геометрии из слота v4 ходьбу не меняет: шаг по-прежнему не сталкивается со стеной.

## Источник геометрии в просмотрщике

Сначала OCCT читает байты BinTools из `exact_geometry` (format v4). Нет байтов, пакет v1–v3, сбой JNI, неподдерживаемый ABI, ошибка чтения, предел памяти или времени — автоматический переход на меш пакета, без падения. Подпись и лог называют выбранный источник. `brep.pack` в этот выбор не входит: это AABB, не точная геометрия.

## Список моделей

FR-M-01. Карточка показывает дату пакета: `manifest.created_utc`, а если её нет — время изменения файла или каталога. Рядом план сверху по `elements.bbox_*` и цвету элемента. Нулевой bbox не рисуется. Каталог `thumbs/` в format_version 1 не пишется, поэтому это не снимок модели и не файл превью.

## CSV спецификации

FR-M-08. Экспорт больше не пишет файл во временный каталог. Вне Android диалог спрашивает папку и кладёт туда `<имя модели>.csv`. На Android тот же текст уходит в системный выбор документа (`ACTION_CREATE_DOCUMENT`). Отмена ничего не пишет. Несуществующая папка не создаётся.

## Системы

FR-M-06 / S2, остаток после этажа, класса и материала. Членство IfcSystem лежит в format_version 2 и сохраняется в версии 3.

- Таблицы `systems` и `system_elements`. Элемент может входить в несколько систем. Новый пакет пишет format_version 4: системы, тайлы и пустой индекс `exact_geometry`.
- Пакет версии 1 открывается как раньше. Систем у него нет, чипов системы нет. Открытие не переписывает файл.
- Версия вне 1…4 отклоняется с текстом, в котором есть номер. Версия 2 или новее без таблиц систем — отдельная ошибка, не пустой список.
- Выбранная система скрывает чужие элементы в дереве и в сцене. «Все системы» и «Показать всё» снимают ограничение.

## Проверка OCCT на Android

Выбрана до смены кодека B-Rep: сначала понять, собирается ли OCCT 7.8.1 под Android и выполняется ли на нём точная операция. Скрипт `tools/android_occt_probe/build_android.sh` собирает модули моделирования и пробу с коробкой и временным BinTools. `format_version` и `brep.pack` не меняются. Сборка API 28 есть для `arm64-v8a` и `x86_64`. Прогон API 28 есть только на эмуляторе Android 9 x86_64: объём 6 м³, площадь 22 м², файл BinTools 4494 байт, 704 мкс, пик RSS процесса 12 892 КБ. Образ API 28 arm64 эмулятор 37.2.13 на хосте x86_64 не включает. Отдельная сборка той же пробы на API 27 запущена на эмуляторе 35.1.21, Android 8.1, `arm64-v8a` (`uname` `aarch64`): те же 6 м³, 22 м² и 4494 байт, 111 726 мкс, пик RSS 13 188 КБ. Это перевод arm64 на x86_64 и одна коробка, не телефон и не API 28. Числа — в [m0_report.md](m0_report.md).

## GUI конвертера

Страница «Конвертер» открывается из библиотеки. Она показывает файлы `.ifc` и `.fbvpkg` и каталоги с `manifest.json`: имя, размер в байтах, дату изменения в UTC и статус. Кнопка запускает внешний `fbvconv` с `--directory --mesher analytic` и пишет каталог `<имя>.fbv` рядом с IFC. Существующий каталог не перезаписывается. Пока процесс идёт, полоса берёт строки `FBV_PROGRESS <сделано> <всего>`: 1/2 после сборки сцены и 2/2 после записи пакета. Это две стадии, не процент по элементам. Журнал — stdout и stderr после выхода процесса. Подписи есть по-русски и по-английски. Это не отдельная программа проводника и не процент по элементам.

## Замечания и BCF

У выбранного элемента можно оставить текст и, если указан путь, файл фото. Запись лежит рядом с пакетом (`<пакет>.remarks.json` и каталог `<пакет>.remarks`), не внутри него. `format_version` и `brep.pack` не меняются. Экспорт пишет ZIP BCF 2.1: у темы один комментарий, точка обзора ссылается на GlobalId элемента, снимок кладётся, если фото было. Импорт читает этот же поднабор и привязывает тему по GlobalId. Тема без элемента в пакете сохраняется и считается. Автор в файле — строка `field-bim-viewer`, отдельной учётной записи нет. Вместе с текстом сохраняется ракурс: положение и направление камеры в координатах пакета (Z-up, без `local_origin`) и активные фильтры (этаж, класс, материал, система, срез, скрытые и изолированные). Открытие замечания ставит этот ракурс. На Android глаз и цель читаются из Filament. Где платформенного вида нет, сохраняется поза ходьбы, а если её нет — кадр на ящик элемента; это не жест орбиты. BCF 2.1 пишет ту же камеру в `viewpoint.bcfv` как `PerspectiveCamera`, уже с прибавленным `local_origin`, чтобы другой просмотрщик открыл место в координатах IFC. Фильтры в BCF не входят. Отдельных именованных видов нет. Сеть, USB и сервер не используются.

## Дальше, этот шаг не начат

- Прогон API 28 `arm64-v8a` на устройстве. Эмулятор API 28 arm64 на этом x86_64 не запускает, к телефону отсюда не подключались. Тестовый APK с пробой OCCT и инструкция, что прислать: [occt_probe_apk.md](occt_probe_apk.md), файл `tools/occt_probe_apk/field-bim-occt-probe-arm64.apk`. Это не просмотрщик и не релиз.
- BinTools (format_version 4). Индекс `exact_geometry` и необязательный файл `geometry/elements/<id>.brep` — байты `BinTools::Write`, не `brep.pack`. `brep.pack` остаётся AABB `analytic-box-v1`. Аналитический мешер форму не пишет, таблица пустая, пакет открывается. Сборка с IfcOpenShell кладёт в этот файл байты формы OCCT из второго итератора (NATIVE), не меняя треугольники. Пакеты v1–v3 и v4 без этих байтов открываются как раньше. FR-M-09, FR-M-10 и контур сечения FR-M-11 эти байты ещё не читают.
- Тайлы (FR-C-15). Сделано в `format_version` 3: один раздел, тайл = `IfcBuildingStorey` × дисциплина. Дисциплина — первое слово системы по возрастанию id (вентиляция, отопление, электрика, водопровод, пожар, архитектура, конструкции, оборудование), иначе таблица класса IFC. Нет этажа или дисциплины — явная корзина, элемент не пропадает. Файлы `mesh/elements/<id>.glb` не дублируются. Пакеты v1 и v2 открываются. Потоковая выгрузка тайла с диска в просмотр не сделана: индекс есть, ридер отдаёт состав.
- Синхронизация (FR-C-17, FR-M-18). Протокол `fbv-sync-1` один и для локальной сети, и для сервера организации. Адрес — настройка библиотеки. В обмен входят пакеты, sidecar замечаний, фото и BCF рядом с пакетом. Новее по времени побеждает, одинаковый SHA-256 не копируется. Облака нет. Описание — [sync.md](sync.md). USB не сделан.

Не начинать, пока нет отдельного задания: iOS, DWG/DXF, IGES, MLT, шифрование и RuStore.
