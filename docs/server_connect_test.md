# Проверка сервера организации по Wi-Fi

Телефон и компьютер в одной сети Wi-Fi. В каталог сервера класть только тестовые пакеты из `testdata/public`. Модели организации туда не копировать.

Это тот же протокол `fbv-sync-1`, что уже есть в приложении. Отдельного облака нет: телефон забирает файлы и дальше открывает их без сети. Ссылка тестовая, обычный HTTP в локальной сети.

## 1. Сервер на Windows

Из корня репозитория:

```
tools\lan_sync_server.bat
```

Нужна команда `dart` из того же Flutter SDK, которым собирается приложение. Если `dart` не находится, из каталога `app`:

```
dart run tool/lan_sync_server.dart --root ..\testdata\public
```

На Linux и macOS из каталога `app`:

```
dart run tool/lan_sync_server.dart --root ../testdata/public
```

Скрипт слушает порт 8080 на всех интерфейсах IPv4 и печатает адрес, токен и ссылку `fbv://connect?...`. Рядом с запуском появляется `sync-link.html` с QR-кодом. Откройте этот файл на компьютере и не закрывайте окно скрипта.

Другой порт: `tools\lan_sync_server.bat --port 8090`

## 2. Адрес компьютера

Скрипт печатает IPv4. Если список пустой или телефон не соединяется, в командной строке:

```
ipconfig
```

Нужен IPv4 адаптера Wi-Fi, обычно `192.168...`. Не `127.0.0.1` и не адрес виртуальной машины, если телефон к ней не подключён. Этот адрес можно вписать в приложении под «Дополнительно».

## 3. Брандмауэр

Windows может спросить разрешение для `dart.exe`. Разрешить частные сети.

Если телефон порт не открывает, в PowerShell от администратора (порт подставьте свой):

```
netsh advfirewall firewall add rule name="FBV sync 8080" dir=in action=allow protocol=TCP localport=8080 profile=private
```

После проверки правило удалить:

```
netsh advfirewall firewall delete rule name="FBV sync 8080"
```

Через окно: «Брандмауэр Защитника Windows» → «Дополнительные параметры» → «Правила для входящих подключений» → «Создать правило» → «Порт» → TCP → 8080 → разрешить → частный профиль.

## 4. Телефон

Собрать приложение у себя и поставить на телефон. Магазин и выпуск не нужны. Debug-сборка достаточна:

```
cd app
flutter pub get
flutter run
```

Либо apk:

```
flutter build apk --debug --target-platform android-arm64
```

Файл: `build\app\outputs\flutter-apk\app-debug.apk`.

Первый запуск: «Подключиться к серверу организации» → «Сканировать QR-код» и навести камеру на QR в `sync-link.html`.

Если камера телефона сама предлагает открыть ссылку, это та же `fbv://connect`. Если не предлагает, в приложении нажать «Дополнительно» и ввести адрес и токен из консоли. Эти поля по умолчанию скрыты.

В списке появятся тестовые модели со значком облака. Следующий запуск забирает модели сам и ничего не спрашивает.

«Настройки → Сервер»: проверить соединение, сменить сервер, забыть сервер.

## 5. Обрыв

Остановить скрипт или выключить Wi-Fi телефона и открыть приложение снова. Текст: «Сервер организации недоступен, показываю сохранённые модели» и кнопка «Повторить». Уже скачанные модели остаются.

Неверный токен сервер отвергает. Приложение просит отсканировать QR ещё раз.

## Чего здесь нет

Кнопка «Слушать» в настройках телефона открывает порт только на самом телефоне (`127.0.0.1`). Для этой проверки она не используется: сервер — скрипт на компьютере. USB-синхронизации нет. Учётной записи нет.
