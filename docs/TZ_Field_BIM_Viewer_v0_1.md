## 1. Назначение и цели

Мобильное приложение (сначала Android, затем iOS; телефоны и планшеты) для просмотра информационных моделей зданий и инженерных CAD-моделей на строительной площадке без доступа к сети. Инженер видит 3D-модель, выбирает элемент касанием и получает его атрибуты, спецификации и точные размеры.

- Ц1. Полный офлайн. После загрузки пакета на устройство никаких сетевых обращений не требуется.
- Ц2. Быстрое открытие крупных моделей за счёт предварительной конвертации на ПК/CI в оптимизированный пакет (меш + SQLite + точная геометрия).
- Ц3. Точность там, где она нужна: измерения и сечения по точной B-Rep-геометрии (OCCT) загружаемой лениво для выбранных элементов.
- Ц4. Модульное ядро: конвейер OCCT → меш → Filament и импорт STEP через OCCT XDE разрабатываются как самостоятельные компоненты; UI опирается на прототип 3DViewer-main (Flutter + Filament).
- Ц5. Отечественные САПР (Renga, nanoCAD, Model Studio CS) и Revit поддерживаются через экспорт в IFC.
## 2. Термины

| Термин | Определение |
| --- | --- |
| Пакет (.fbvpkg) | Офлайн-контейнер модели, результат работы конвертера (раздел 7) |
| Меш отображения | Триангулированная геометрия для рендеринга (GLB или собственный бинарный формат), с LOD и инстансингом |
| Точная геометрия | B-Rep-тела OCCT (TopoDS_Shape / XDE) по каждому элементу; загружаются по требованию |
| ElementId | Сквозной целочисленный идентификатор элемента в пакете; связывает меш, SQLite и B-Rep; соответствует IFC GlobalId / пути в сборке STEP |
| XDE | OCCT Extended Data Exchange — STEP/IGES с именами, цветами, слоями, сборками |
| Pset / Qto | Наборы свойств и количественных характеристик IFC |
| LOD | Уровень детализации меша |

## 4. Границы проекта

### 4.1 Входит в MVP

- Конвертер (CLI, Windows и Linux; запуск в CI/Docker): IFC 2x3, IFC4, IFC4.3 → пакет; STEP AP203/AP214/AP242 → пакет.
- Android-приложение (arm64-v8a), телефоны и планшеты: открытие пакета, навигация, выбор, свойства, дерево, поиск, фильтры, измерения, сечения.
- Нативное C++-ядро на OCCT 7.8.1 для работы с точной геометрией на устройстве.
### 4.2 Следующие этапы

- iOS (iPhone/iPad).
- IGES (технически через тот же XDE, низкий приоритет).
- 2D-подложки DWG/DXF.
- Замечания/фото/BCF (см. ОВ-5).
### 4.3 Не входит

- Редактирование модели, обратная запись в IFC/STEP.
- Прямое чтение RVT, Renga, nanoCAD, Model Studio CS — только через их IFC-экспорт.
- Облачная синхронизация и сетевые функции в MVP.

## 6. Архитектура (гибрид)

Тяжёлая работа (разбор IFC/STEP, булевы операции IfcOpenShell, триангуляция, упрощение, извлечение свойств) выполняется на ПК/CI. Устройство получает готовый меш и SQLite для мгновенного просмотра, а точную B-Rep-геометрию загружает только для выбранных элементов — для измерений и сечений.

## 7. Формат офлайн-пакета (.fbvpkg)

Пакет — ZIP-контейнер без сжатия для крупных бинарных частей (STORED, чтение через mmap/смещения) либо каталог с тем же составом. Версионируется полем format_version в manifest.json.

model.fbvpkg

├── manifest.json        версия формата, источник (файл, хэш, схема IFC), единицы, локальный origin

│                        (сдвиг в float64), bbox, счётчики, список LOD, хэши частей

├── mesh/

│   ├── lod0.glb         полная детализация; EXT_mesh_gpu_instancing; узел/примитив на ElementId

│   ├── lod1.glb         упрощённый (meshoptimizer), опционально lod2

│   └── tiles/*.glb      (опционально) разбиение по этажам/пространственным ячейкам

├── meta.sqlite          атрибуты, свойства, спецификации, FTS5

├── brep.pack            точная геометрия: BinTools-потоки, zstd, по одному на элемент/тип

├── brep.index           ElementId → (offset, length, codec, shape_ref, transform)

└── thumbs/              превью модели и этажей

### 7.1 Схема meta.sqlite (основные таблицы)

| Таблица | Поля (ключевые) |
| --- | --- |
| elements | id PK, guid, ifc_class, name, tag, type_id, storey_id, parent_id, material_set_id, bbox_min/max, mesh_node, brep_ref, color |
| spatial | id, kind (Project/Site/Building/Storey/Space), name, elevation, parent_id |
| types | id, guid, ifc_class, name, predefined_type |
| psets / props | pset(id, element_id\|type_id, name, source: instance/type); prop(pset_id, name, value_text, value_num, unit, data_type) |
| quantities | element_id, qset, name, value, unit, kind (Length/Area/Volume/Count/Weight) |
| materials | id, name, category; material_layers(set_id, material_id, thickness, order) |
| classification | element_id, system (напр. КСИ/Uniclass/OmniClass), code, title |
| assembly (STEP) | id, parent_id, name, instance_transform, color — дерево XDE |
| fts_elements | FTS5 по name, tag, guid, type name, значениям свойств |
| spec_views | предрассчитанные сводки (тип × материал × количество) по этажам |

### 7.2 Правила

- Координаты меша — float32 относительно локального origin (manifest), чтобы исключить потерю точности на геопривязанных моделях; B-Rep хранится в float64 в исходной системе + тот же сдвиг.
- Единицы в пакете — метры; исходные единицы фиксируются в manifest; в UI — мм.
- Одинаковые IfcRepresentationMap / инстансы сборок STEP хранятся один раз (меш и B-Rep) + матрицы.
- Пакет самодостаточен: на устройстве не требуется ни исходный IFC/STEP, ни сеть.
