# Тестовый APK с пробой OCCT

Это не просмотрщик и не релиз. Файл `tools/occt_probe_apk/field-bim-occt-probe-arm64.apk` — отладочный пакет только для `arm64-v8a`, `versionName` `0.2-probe`, `targetSdk` 34. Внутри исполняемый файл пробы (в пакете он называется `libocct_probe.so`, интерпретатор `/system/bin/linker64`, метка ELF API 28) и библиотека `libocct_probe_jni.so` с тем же замером. Рядом девять библиотек OCCT и `libc++_shared.so`. Замер — ящик 1×2×3 м, ожидаемые объём 6 м³ и площадь 22 м². С этой машины пакет на телефон не ставился.

## Что уже видно по первому пакету

Первый пакет (`0.1-probe`, `targetSdk` 28) на свежем Samsung запускал копию из `filesDir`. Экран показал только `exit=139` и путь `.../files/occt_probe`: это SIGSEGV, а код возвращал результат первой попытки и до файла в `nativeLibraryDir` не доходил. Первая строка пробы печаталась только после всего замера, поэтому пустой stdout не отделяет падение загрузчика от падения внутри OCCT.

По самим ELF этого пакета проверено на машине сборки, не на телефоне: у `libocct_probe.so`, девяти `libTK*.so` и `libc++_shared.so` нет сегмента `PT_TLS`. Проверка Bionic «выравнивание TLS исполняемого файла не меньше 64 байт на arm64» выполняется только если сегмент есть; у этой сборки его нет. `LD_LIBRARY_PATH` в том запуске уже выставлялся в `nativeLibraryDir`. Сборка пробы — API 28, NDK 28.2; `crtbegin` этой платформы пустой TLS-сегмент не добавляет, в отличие от `crtbegin` API 29 и новее. Из-за этого платформу линковки не поднимали.

## Как поставить

1. Удалите старое приложение «OCCT probe», если оно осталось.
2. Скопируйте новый APK на телефон. Телефон — arm64.
3. Откройте файл и разрешите установку из этого источника, если система спросит. `targetSdk` 34, чтобы Play Защита не считала пакет собранным для старого Android.

Кнопка «Запустить пробу» запускает `libocct_probe.so` из `nativeLibraryDir` и ставит `LD_LIBRARY_PATH` в тот же каталог. Библиотеки извлекаются на диск (`extractNativeLibs=true`). Вторая кнопка грузит `libocct_probe_jni.so` через `System.loadLibrary` в отдельном процессе `:jni`. В `filesDir` проба больше не копируется.

## Что прислать

Нажмите обе кнопки по очереди. После каждой пришлите весь текст с экрана, его можно выделить. В тексте уже есть `sdk`, `abis`, пути, `exit` и, если процесс убит сигналом, номер сигнала. Отдельно подключаться к телефону не нужно.

У удачного запуска есть `marker exe_init`, затем `marker main before_occt`, дальше `marker box`, `marker bintools_write`, `marker roundtrip` и строка `ok volume_m3=6 area_m2=22`, в конце `exit=0`. `marker exe_init` пишется после конструкторов уже загруженных библиотек и до `main`. Если его нет, а `exit` снова 139, падение раньше нашего кода: загрузчик или статический инициализатор OCCT. Если `marker main before_occt` есть, а следующего маркера нет, оборвался названный шаг.
