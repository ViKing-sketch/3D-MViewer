# M0. Прототип on-device OCCT и бенчмарк конвертера

Статус on-device: **не выполнялся**.

Бенчмарк конвертера на ПК — вывод `fbvconv --stats --json <файл>`. Это не замер on-device OCCT из таблицы ниже, а числа для выбора мешера и оценки памяти на хосте. Поля JSON:

| Поле | Смысл |
| --- | --- |
| `elements`, `with_mesh`, `failed`, `without_geometry` | Все элементы, с мешем, с представлением но без меша, без представления |
| `triangles` | Треугольники lod0 |
| `completeness` | `ok`, если GlobalId IfcElement не потерян |
| `peak_rss_bytes` | Пик RSS процесса |
| `package_bytes` | Размер пакета |
| `timings_s.parse`, `.geometry`, `.write`, `.total` | Секунды |
| `mesher`, `geometry_kernel`, `threads` | Какой мешер отработал |

Атрибутный разбор держит текст IFC в памяти. IfcOpenShell открывает тот же путь с диска и тоже держит модель. Поэлементные GLB пишутся по одному, BIN `lod0.glb` стримится во временные файлы, буфер элемента освобождается после копии. Пик — разобранный IFC, кэш форм OCCT на время итератора и текущий элемент. Для файлов в несколько гигабайт нужен запас RAM выше размера IFC; пакет при этом пишется в каталог поэтапно, а не одним буфером.

Прогон `linux-gcc-ifcopenshell` (Release, 4 потока, допуск 0.01 м). Образцы IfcOpenShell/files (`20a17fc`) и файлы из `testdata/`. `sample_wall` — 3/4, потому что у прокси нет представления (`failed` = 0). Остальные — все элементы с телом получили меш, `completeness` = ok.

# Прототип on-device OCCT

ТЗ (этап M0) требует сборку OCCT 7.8.1 под Android NDK, импорт STEP через XDE на устройстве и сравнение с заранее сконвертированным GLB в Filament. Нужны не меньше двух устройств и трёх моделей (малая / средняя / крупная). В этой среде нет NDK-сборки OCCT и нет прогона на устройствах, поэтому решения go/no-go по объёму OCCT на устройстве нет. Числовые цели раздела 9 ТЗ остаются допущениями [П].

Пресет CMake `android-arm64` подключает toolchain NDK (`ANDROID_NDK_HOME`) и останавливается с понятной ошибкой, если NDK нет. Superbuild хоста описан в `deps/CMakeLists.txt` и включается `FBV_WITH_IFCOPENSHELL`.

Когда прогон появится, отчёт заполняется так:

| Модель | Устройство | Загрузка STEP, с | Пик RSS, МБ | Триангуляция, с | FPS | Размер .so, МБ |
| --- | --- | --- | --- | --- | --- | --- |
| малая | | | | | | |
| средняя | | | | | | |
| крупная | | | | | | |

Рядом — те же модели, открытые как GLB в Filament, и вывод: оставляем ли на устройстве только чтение `brep.pack` (рекомендация риска R1) или допускаем on-device STEP.
